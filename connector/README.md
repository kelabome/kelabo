# connector/ — the agent bridge, and the packages built from it

Attaches a developer's **own** coding agent to a kelabo. Kelabo supplies
a token and a channel; their model, MCP servers, permissions and working
directory stay entirely theirs and are never read or written here.

Design: [`docs/components/16-agent-bridge.md`](../docs/components/16-agent-bridge.md)
for the interface, [`17-agent-distribution.md`](../docs/components/17-agent-distribution.md)
for how it is packaged and installed.

When the kelabo is part of a journey — the container that carries decisions and
documents across related kelabos ([`docs/20-journey.md`](../docs/20-journey.md)) —
the agent can read it and write back through the `kelabo_journey_*` tools:
info, timeline and pinned board, submitting its own synthesis as a report, and
posting a board message when the journey's owner has allowed AI posts.

**This directory's `package.json` is `private` and is never published.** It
carries `"@kelabo/contracts": "file:../contracts"`, which npm cannot resolve
anywhere but this repository. What ships is generated by `build/pack.mjs`.

## Layout

| Path | What |
|---|---|
| `src/index.js` | `startBridge()` — the MCP server, the tunnel, the queue, the binding. No CLI |
| `src/cli.js` | the `bin`: `setup`, `login`, `status`, `uninstall`, `reset`, `run` |
| `src/runtimes.js` | the runtime registry: config file, MCP entry shape, detection, launch line |
| `src/launch.js` | `kelabo opencode` / `kelabo claude`: the flags nobody should have to remember, and the `--` boundary |
| `src/install.js` | **pure** — which config keys each runtime gets, and how to take them back out |
| `src/installer.js` | the fs half: discover, back up, write, remember |
| `src/plugin/opencode.js` | the opencode plugin. One copy, used by npm *and* the Rig; wired as a `file:` spec so there is only ever one on disk |
| `src/adapters/` | Contract C: injecting transcript, per runtime. `index.js` maps `KELABO_RUNTIME` to one |
| `src/envelope.js`, `src/transcriptQueue.js` | **pure** — what the agent sees, and when |
| `commands/` | `/kstart` and `/kend`, as markdown with front matter. opencode only |
| `build/pack.mjs` | emits `dist/agent/`, ready for `npm publish` |

## Working on it

```bash
npm test            # queue + envelope + persona + install + runtimes + launch + channel (pure) + smoke + pack
npm run pack        # build the publishable directories into dist/
node src/cli.js setup --config /tmp/scratch.json --dry-run
```

`src/install.js`, `src/envelope.js` and `src/transcriptQueue.js` are pure — no
fs, no fetch, no clock — so plain node can exercise them. They are also each the
place where a mistake is otherwise only findable in a live kelabo, or in
someone else's already-damaged config. Keep new batching, framing or
config-editing logic there rather than in an adapter or the CLI.

`test/smoke.mjs` drives the whole bridge against a fake Gateway and a **stub
adapter**, which is what proves the tool surface is runtime-independent without
opencode or Claude Code installed.

## Using it from this checkout

`kelabo setup` works from source — it writes the absolute path of
`connector/src/cli.js` into your config, so edits take effect on the next session
with no reinstall:

```bash
node src/cli.js setup --all                    # wire every runtime on this machine
node src/cli.js opencode                       # start it: free port, background subagents
node src/cli.js claude -- --resume             # start it: channel flag on; `--` forwards
node src/cli.js opencode --dry-run             # print the composed command, start nothing
node src/cli.js status                         # what is paired, wired and running
```

Or install it the way a user would, from the repo root:

```bash
make install-oc-connector      # pack a real tarball, npm i -g, wire opencode
make install-cc-connector      # …and Claude Code; they coexist
make uninstall-connector       # unwire everything, drop the credential, npm rm -g
```

## Releasing

```bash
npm version <patch|minor|major>
npm run pack
npm test
npm publish dist/agent --access public
```

`test/pack.mjs` is the gate: it asserts each emitted manifest has no `file:`
dependency, that `@kelabo/contracts` and zod are inlined rather than imported,
that every bare import is a declared dependency, that the opencode plugin has the
`export default { id, server() }` shape opencode 1.18+ requires of an npm plugin,
and that **both injection paths survive bundling** — tree-shaking either one
would leave the runtime that needs it with an MCP server that dies on start.

## Environment

| Variable | Default | Purpose |
|---|---|---|
| `KELABO_RUNTIME` | written by `setup` | Which adapter `kelabo run` uses. Lives in the MCP entry, not in your shell |
| `KELABO_AGENT_FILE` | `~/.kelabo/agent.json` | Credential location |
| `KELABO_INSTALL_FILE` | `~/.kelabo/install-<runtime>.json` | What `setup` wrote, so `uninstall` can undo exactly that |
| `KELABO_BRIDGE_LOCK` | `~/.kelabo/bridge-<opencode pid>.json` | Where this bridge publishes its loopback port |
| `KELABO_CONTROL_PORT` | `4190` | Loopback listener for the `/kstart` handover (opencode) |
| `CLAUDE_CONFIG_DIR` | `~` | Where `.claude.json` lives; `setup` follows it |
| `KELABO_GATEWAY_URL` | from the credential | Override the Gateway |
| `KELABO_MAX_BACKLOG` | `60` | Transcript messages held while the agent is busy |

## Claude Code

`kelabo setup --runtime claude-code` writes **one** key —
`mcpServers.kelabo` in `~/.claude.json` — because the channel targets the session
that spawned the MCP server: no plugin, no handover, no `/kstart`. Launch with
`claude --dangerously-load-development-channels server:kelabo`.

Two things about this runtime that nothing reports, both verified against 2.1.220
and both covered by `test/channel.mjs`:

- **`instructions` are truncated to 2048 characters.** The persona is 5820, so
  sending it whole silently dropped the prompt-injection gate. `persona.js`
  splits into `PERSONA_CORE` (system prompt) and `PERSONA` (returned by
  `kelabo_join`). See docs 16 §4.2.
- **A channel nobody enabled drops notifications with no error.** The adapter
  reads its own parent process's command line to see whether the launch flag
  names this server, and surfaces the remedy through `kelabo_join`. It reports
  `null` rather than a warning when it cannot tell.

`meta` keys must be identifiers — hyphenated keys are dropped in flight, so
`metaFor()` filters at the source where a test can see it.

Kelabo deliberately does **not** declare `claude/channel/permission`. That
capability relays tool-approval prompts out through the channel, and the far end
of this one is a kelabo room that may contain link-joined guests.
